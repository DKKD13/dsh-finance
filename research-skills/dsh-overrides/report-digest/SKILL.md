# Report Digest — 研报快速摘要

**用途**：把卖方研报、纪要、会议记录、行业报告快速消化成可读的人话。**不是翻译，是提炼**。

**不是干什么**：不是做深度公司分析（那是 `research` skill）。本 skill 假设输入材料已经存在，你的工作是萃取和重组，不是从零研究。

**材料范围**：用户限定一份材料时，只读取该材料及完成任务必需且获准的附件；不要为找写作风格读取旧摘要或其他研究稿。原文自己的缺口说明也需要与已读数字和附件核对，发现矛盾就指出，不能因“作者说过”直接继承为事实。

## 5 条标准

1. **说人话** — 不翻译原文。用自己的话讲报告到底在说什么。卖方套话直接跳过（"凸显公司竞争优势"、"赋能业务增长" 之类的废话）。
2. **完整逻辑链** — 作者看到了什么 → 得出什么结论 → 数字支撑是什么。只呈现原文有依据的环节，缺环节说明缺口，不替作者补造或反驳其未提出的主张。观察/同比差异不等于因果，也不足以肯定或排除某个原因、给解释排“最可能”。
3. **增量优先** — 多份报告时，前面已讲过的观点简单带过，篇幅留给这份报告独有的视角和发现。
4. **关键数字用表格** — 财务预测、估值参数、数据对比不埋在文字里。核心图表提取数据点重新呈现，保留数字定义、单位、分母和可比期间；派生数值用确定性计算，核对实际返回，若保存则读回最终正文，确认公式/输入/结果与标签一致。
5. **事实 vs 观点** — 公司已披露数据 vs 分析师推演/假设，明确区分。发行人关于纪录/原因的自述要归属发行人；同一发行人的正文与附件不算独立交叉核验，不能把金额/同比对上升级为纪录或因果已证实。

## 信息源信任分级

参见 `../_investment-philosophy.md` §3（信任锚分级）。简而言之：sell-side 研报是"事实的基础但有滤镜"。提炼时要分清：

- **原始数据**（公司披露 / 第三方数据）→ 信任高
- **卖方解读**（增长率假设 / 目标价 / 评级）→ 信任中等
- **卖方叙事**（行业 narrative / 产品评价）→ 信任低，往往是 promotional

## 输出格式

- **顶部 takeaway**（3 句话）：这份报告的核心结论是什么
- **关键数字表格**：从图表里提取，不要放图片
- **增量观点**：相对于 sell-side 共识，这份报告新的视角是什么？无共识材料则说明无法比较。
- **疑问与盲区**：作者没回答但应该回答的问题；区分正文未解释、附件已披露与尚未读到，只写有依据的缺口。逐项说清缺少哪条记录、字段或期间；下“没有／全空白”等全称判断前，检查已读表格与正文是否已有部分信息，不能把不完整扩大成完全缺失。
- **如果是多份报告**：最后加一个 "对比" 段落，列出关键分歧

## ✅ 完成判据

- 没有任何"原文复述"段落（全部是你的话）
- 所有关键数字提取到表格
- 有材料依据才给出增量或盲区，标明依据与推断边界；无依据明确缺口，不强凑“作者没说”的洞察。

## 不要

- 不要给买卖建议 — 你只是在消化材料，不是出投资报告
- 不要补充材料外的内容 — 那是 `research` skill 的事
- 不要把高低端点之间的线性位置称为统计分位；后者需要观察值分布，也不能无据断言区间端点不可达到。
- 不要将缺完整历史写成无比较基准；已有前收等基准仍可作对应比较，趋势/历史位置变化另需可比序列。
- 不要复述卖方套话 — 看到 "凸显" "赋能" "助力" "护城河" 这种词直接跳过原文，用人话重写
