## 为什么必须独立成一步

FEV 里的 Fundamentals（生意怎么样）是为估值服务的，很容易直接滑向数字和 DCF。但没有对生意本身的透彻理解，所有数字都是浮的 —— 你不知道哪个数字是核心驱动、哪个是噪音，也不知道护城河到底靠什么成立。**先理解、后判断**：把 "看懂生意" 和 "判断价格" 物理分开。



***

## 四层理解框架

### 第一层：业务全景 — 它到底做什么、卖什么



* **业务线拆解**：每条线卖什么物理产品 / 服务？交付形态是芯片 / 板卡 / 机架系统 / 软件 / 订阅 / IP 授权？

* **客户是谁**：客户类型（云厂 / OEM / 企业 / 消费者 / 政府）、客户集中度（前五大占比）、地域分布。

* **收入怎么确认**：一次性卖断 / 长期框架协议 / 订阅 / 授权费 / 分成。

* 产出一张「业务线 — 产品 — 客户 — 收入确认方式」对照表。

### 第二层：商业模式 — 它怎么赚钱、凭什么是它



* **价值主张**：客户为什么买它而不是对手？（性能 / 成本 / 供应安全 / 生态 / 迁移成本）—— 要具体到客户的采购决策。

* **商业模式类型**：fabless / IDM / IP 授权 / 平台 / 订阅 /razor-and-blade……

* **单位经济学（unit economics）**：单位产品的价格 — 成本 — 毛利结构；什么在驱动单位经济改善或恶化。

* **关键资源与关键活动**：什么是必须握在手里的（设计能力 / 先进产能 / 生态 / 数据 / 品牌）。

* **商业模式迁移**：有没有 "第二增长曲线" 正在改变赚钱方式（如卖芯片 → 卖机架系统 + 长期协议）。

### 第三层：产业链与利润池 — 价值在哪、谁拿走超额利润



* **产业链地图**：上游（设备 / 材料 / 代工 / 存储 / IP / EDA）→ 本公司 → 下游（OEM / 云厂 / 渠道 / 终端）。

* 每个环节的：集中度、议价能力、资本密集度、典型毛利 / 净利。

* **利润池分析**：行业总利润在各环节如何分布、正在流向谁、本公司在哪个环节、有没有能力向高利润环节移动。

* **依赖与风险**：对单一供应商 / 客户 / 技术节点 / 地理的依赖。

### 第四层：行业本质与特性 — 这门生意的底层规律



* **生命周期**：导入 / 成长 / 成熟 / 衰退；当前渗透率与未来增长驱动。

* **核心特性**（按需勾选并解释，不是贴标签）：周期性 / 资本密集 / 技术快速迭代 / 规模经济 / 网络效应与生态锁定 / 高转换成本 / 牌照监管 / 地缘约束。

* **竞争结构**：集中度（CR3/CR5）、竞争维度（价格 / 技术 / 生态 / 服务）、进入壁垒。

* **护城河**：成本优势 / 网络效应 / 无形资产 / 转换成本 / 规模效应 —— 必须讲清**机制**，以及什么会摧毁它。

* **范式变迁**：正在发生的技术变化会不会重写行业规则、谁受益谁受损。

## 产出契约



* 一份「商业模式与行业本质」研究，**不含估值、目标价、评级**。

* 必含：业务 - 客户 - 收入对照表、产业链地图、单位经济学、利润池分布、行业特性与护城河机制。

* 每个关键事实标 \[来源，日期]；明确区分**事实 / 行业共识 / 我的推断**。

* 完成后才进入 FEV—— 此时 Fundamentals 应建立在对生意的透彻理解上，而非数字罗列。

## Stage 0 Gate — 自检（全过才能进 FEV）



1. 能用三句话向一个外行讲清：它做什么、靠什么赚钱。

2. 说得出这个行业**谁最赚钱、为什么**，以及这家公司在不在那个位置。

3. 说得出这门生意最大的一条底层规律（周期 / 生态锁定 / 规模效应……）。

4. 说得出护城河的**具体机制**，以及什么会摧毁它。

5. 全程没有跳到估值 —— 这一步只谈生意本身。
